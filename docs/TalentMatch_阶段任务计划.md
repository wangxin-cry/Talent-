## 阶段 1：环境 + 数据库空壳（2.5 天）

**要干什么**

1. 装后端依赖：用 conda 里的 `py311` 环境，一次性装 FastAPI、SQLAlchemy、Alembic、bcrypt、python-jose、pdfplumber、PyMuPDF、python-docx、openpyxl、pytest、openai。装完 `python -c "import fastapi"` 不报错。
2. 建目录：`backend/`（后端）、`frontend/`（前端）、`docs/`（文档）、`samples/`（样例简历）。
3. 建 9 张表（先不管业务逻辑，只建结构）：
   - `companies` 公司
   - `users` 用户（带角色字段）
   - `jobs` 职位
   - `candidates` 候选人
   - `resumes` 解析后的简历内容
   - `resume_files` 上传的原始文件（PDF/Word）
   - `applications` 应聘记录（谁投了哪个职位、什么状态）
   - `match_results` 匹配结果（分数 + 命中的技能 + 缺的技能）
   - `ai_calls` 每次调 AI 的记录（用了多少 token、花多少钱）
4. 生成数据库文件 `talentmatch.db`，跑一次建表（开发用 SQLite，省得装数据库）。
5. 后端加两个接口：`GET /healthz`（返回数据库是否正常）、`GET /`（返回版本号）。
6. 前端跑一个空白首页，显示 "TalentMatch"。
7. 写 `scripts/dev.ps1`：一个命令同时起后端和前端。

**做完你怎么确认**

- 浏览器打开 `http://localhost:8000/docs`，能看到接口列表，点 `GET /healthz` 返回 `{"db":"ok"}`。
- 浏览器打开 `http://localhost:3000`，有页面，写着 TalentMatch。
- 用 SQLite 工具或 `python -c "import sqlite3;..."` 能看到 9 张表。
- 执行 `scripts/dev.ps1`，两个服务都起来。

**这阶段不做什么**：登录、职位、简历、任何业务功能。**只有空壳，这是故意的。**

## 阶段 2：登录和三种角色（2.5 天）

**要干什么**

1. 用户表已经有角色字段，现在规定三种：招聘专员（`recruiter`）、用人经理（`manager`）、管理员（`admin`）。
2. 写 4 个接口：注册、登录（发 JWT token）、查当前用户、退出登录。
3. 密码用 bcrypt 加盐哈希存，数据库里绝不能看到明文。
4. 预置 3 个演示账号（每个角色一个），密码统一 `123456`。
5. 前端做登录页：输邮箱密码 → 成功后跳到工作台；token 存起来，之后每个请求带上。
6. 加路由守卫：没登录访问任何业务页，自动踢回登录页。
7. 菜单按角色显示：招聘专员看不到"成本/用户管理"，管理员能看到全部。

**做完你怎么确认**

- 打开 `/login`，用 `recruiter@demo.com / 123456` 登录 → 进工作台，左边菜单只有招聘相关。
- 换 `admin@demo.com` 登录 → 菜单多出"用户管理""成本"。
- 复制工作台地址，退出登录后再粘贴访问 → 被踢回 `/login`。
- 数据库里 `users.password` 是一串 `$2b$...`，不是 `123456`。

**这阶段不做什么**：邮箱验证、找回密码、API Key、用户管理页面（管理员的菜单先留着，点进去可以是空页）。

## 阶段 3：建职位（3 天）

**要干什么**

1. 职位接口：新建、编辑、列表（带搜索）、发布、关闭、归档。
2. 做一张技能词表（先 200 条），作用是统一叫法：`K8s`→`Kubernetes`、`JS`→`JavaScript`、`后端开发`→`Backend`。
3. 做"AI 帮我写 JD"按钮：输入职位名 + 3 个关键词，生成三段（职责 / 要求 / 技能清单），生成结果填进表单，人可以改。
4. 前端职位列表页（卡片 + 搜索框 + 状态筛选）、新建表单、职位详情页。
5. 发布前校验：要求不能为空、技能至少 1 个，否则不让发布。

**做完你怎么确认**

- 新建"Python 后端工程师"，点 AI 生成 → 三段文字自动填好，改两个字 → 保存 → 发布。
- 列表里能看到它，状态"招聘中"；搜索"Python"能搜到。
- 把要求清空再发布 → 提示"任职要求不能为空"，发布不了。

**这阶段不做什么**：多级审批、职位模板、招聘渠道配置。

---

## 阶段 4：上传简历并解析（5 天）

**要干什么**

1. 上传接口：一次能传多份文件，文件存到本地磁盘（文件名用随机 ID，不能用中文姓名），立刻返回"已收到，正在解析"。
2. 解析分三种情况：
   - PDF：先用 `pdfplumber` 抽文字，抽出来是乱码就换 `PyMuPDF` 再抽一次。
   - Word：用 `python-docx` 抽。
   - 图片：先标记"不支持"，后面再补（或直接调视觉大模型）。
3. 调大模型把简历文字变成结构化字段：姓名、手机、邮箱、城市、学历、学校、工作经历（公司/职位/起止时间）、技能、项目。
4. 大模型返回的 JSON 要校验：包在代码块里、少字段、多解释，都要能修好或重试；实在不行就用规则兜底，不能整条丢掉。
5. 字段清洗：手机号去掉空格横线、日期统一成 `2021-03`、技能对上词表。
6. 去重：邮箱或手机号相同 = 同一个人，把两份简历合并成一个候选人（不能只看姓名）。
7. 前端两个页：上传页（拖拽 + 进度条）、解析结果页（左边原文、右边可编辑表单，低置信度字段标黄）。

**做完你怎么确认**

- 传 3 份 PDF + 1 份 Word，几分钟内都出结构化结果。
- 打开一份，右边表单有姓名/电话/工作经历，改一个字段能保存。
- 同一个人的 PDF 和 Word 各传一次 → 候选人只有 1 条，简历挂了 2 个文件。
- 拿一份扫描件/乱码 PDF 传 → 不报 500，会显示"解析失败，可手动录入"。

**这阶段不做什么**：100 份压测、失败自动重试队列、图片 OCR 精调。

## 阶段 5：匹配打分（5 天）

**要干什么**

1. 把简历和职位都变成能比较的数字：
   - 必备技能命中几个、缺几个；
   - 加分技能命中几个；
   - 总工作年限、相关年限；
   - 学历够不够。
2. 打分公式（先按这个，不要自己发明）：`技能 50% + 经验 30% + 学历 12% + 其他 8%`，满分 100。缺必备技能要打 6 折惩罚。
3. 生成匹配理由：命中哪些技能、缺哪些、经验差多少、给一句建议。先用固定模板拼，接大模型润色是加分项。
4. 批量算：一个职位对全库候选人算一遍，结果存进 `match_results`；同一个职位再点一次直接用上次结果，不重复算、不重复花钱。
5. 前端：职位详情页加"智能匹配"按钮 → 出排名表（分数、姓名、命中技能、缺的技能）→ 点一行展开理由。
6. 拿 20 条人工标注的简历（你自己判断"合适/一般/不合适"）算一致率，把数字写进 README。

**做完你怎么确认**

- 点"智能匹配"，10 秒内出排名表。
- 第 1 名点开：能看到"命中 Java、Spring Boot；缺 Kubernetes；经验 5 年 vs 要求 3 年"。
- 同一职位再点一次 → 秒出（走缓存），`ai_calls` 没有新增记录。
- README 里有一致率数字（例如 85%），并能说清怎么算的。

**这阶段不做什么**：人才库推荐、多组权重对比、HR 反馈回流。

## 阶段 6：候选人流程（3 天）

**要干什么**

1. 定状态：`新申请 → 筛选中 → 面试中 → offer → 入职`；任何状态都可以 → `淘汰`（必须填原因）。
2. 后端做状态校验：只能按上面这条线走，非法跳转（比如"新申请"直接跳"offer"）返回错误并说明允许去哪。
3. 每次改状态记一条历史：谁改的、什么时候、从哪到哪、原因。
4. 前端三个地方：候选人列表、候选人档案页（简历 + 匹配理由 + 状态时间线）、按状态分列的流程看板（拖卡片改状态）。
5. 站内通知：状态一变，给操作人一条站内消息（不用发邮件）。

**做完你怎么确认**

- 把候选人从"新申请"拖到"面试中" → 成功，时间线多一条记录。
- 想直接拖到"offer" → 被拒绝，提示"只能先进入面试中"。
- 淘汰时不填原因 → 保存不了。
- 右上角通知图标有 1 条新消息，内容对得上刚才的操作。

**这阶段不做什么**：邮件通知、日历邀请、SLA 超时告警、候选人自助投递页。

---

## 阶段 7：AI 面试题（2 天）

**要干什么**

1. 接口：传入职位 + 候选人，生成 6~8 道面试题，每题带"考察点"和一句"期望听到什么"。
2. 提示词里写死要求：**每道题必须提到简历里的具体项目，或他缺的那项技能**，不许出"请自我介绍"这种通用题。
3. 结果存库；同样的职位 + 候选人再点，直接读上次的，不重复花钱。
4. 前端：候选人详情页加"生成面试题"按钮，卡片展示，能勾选、能复制。

**做完你怎么确认**

- 点生成，出 8 道题，随便抽 10 道看：至少 7 道提到了他的项目名或缺口技能。
- 再点一次 → 秒出（缓存），不新增 AI 调用记录。

**这阶段不做什么**：评分表、面试记录、面试报告。

---

## 阶段 8：数据看板（3 天）

**要干什么**

1. 算 4 个数字：在招职位数、本周投递数、待面试人数、平均招聘天数（从投递到入职）。
2. 漏斗：新申请 → 筛选 → 面试 → offer → 入职，每一步多少人。
3. 渠道：简历来源（官网/内推/猎头/其他）各多少份。
4. 前端一页看板：4 张数字卡 + 1 个漏斗图 + 1 个渠道柱状图。
5. 每个图旁边标一句口径（比如"平均天数 = 投递到入职的中位数"），免得被问住。

**做完你怎么确认**

- 看板上的 4 个数字，用 SQL 从数据库数一遍，完全一致。
- 漏斗能看出哪一步掉人最多（比如"筛选→面试"掉一半）。
- 造 3 条不同渠道的应聘，渠道图能区分开。

**这阶段不做什么**：Excel 导出、成本分析、趋势折线图。

## 阶段 9：收尾，能演示（2.5 天）

**要干什么**

1. 造演示数据：1 家公司、3 个账号、3 个职位、10 份简历、20 条应聘（脚本一键生成）。
2. 写 `README.md`：怎么装、怎么启动、三个账号密码、演示步骤。
3. 一条命令启动：`scripts/dev.ps1` 起后端 + 前端。
4. 写 5 分钟演示脚本，自己空跑一遍，卡住的地方就修。
5. 用真实数据跑一遍全流程，把准确率和耗时记下来（简历解析准确率、匹配一致率、匹配耗时）。

**做完你怎么确认**

- 关掉所有服务，只按 README 操作，10 分钟内能跑起来。
- 演示一遍：建职位 → 传简历 → 匹配 → 看理由 → 生成面试题 → 推状态 → 看板，不卡壳、不报错。
- README 里有 3 个准确率/耗时数字。

**这阶段不做什么**：Docker、部署文档三件套、安全加固、自动化测试全覆盖。

## 每个阶段都要守的 4 条规矩

1. **每阶段结束必须能跑**：不要留下"下周再修"的半成品，跑不起来就别进下一阶段。
2. **每个阶段至少 2 条测试**：不是覆盖率，是"这个功能坏了会红"的最低保障（比如登录错密码、非法状态跳转）。
3. **每阶段一次 git 提交**：提交信息写清做了什么，出问题能回退。
4. **涉及钱和隐私的地方当场做对**：密码不存明文、手机号列表打码、调 AI 要记账——这三件事补起来比一开始就做贵十倍。
